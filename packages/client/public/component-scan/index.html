Part 1

The plan

What we build, in what order, and what has to happen first.

01The guardrails

What an editor can and can't do

Editors keep full control of the words, images and links. The layout decisions that make pages drift move out of their hands and into the theme. Each rule is a standard WordPress setting.

✓

Editors can

  • Start from one of 7 page templatesStandard, Case study, Team bio, Webinar, On-demand webinar, Solution, White paper. Templates registered in the theme, each with its sections in a fixed order.
  • Add sections from the 15 componentsEach one is a locked pattern or block: templateLock: "contentOnly". Text, images and links change. Layout and spacing don't.
  • Pick spacing, type size and color from short lists7 spacing steps, 7 type sizes, the brand palette: spacingSizes, fontSizes, palette in theme.json.
  • Choose what fills the middle of a case studyContent, media, stats or a CTA band, from an allowed list: allowedBlocks on the template's middle area.
✕

Editors can't

  • Type a pixel value for spacing or text sizecustomSpacingSize: false, customFontSize: false, color.custom: false.
  • Add spacer blocksRemoved from the inserter with the allowed_block_types_all filter. Components bring their own top and bottom spacing.
  • Paste raw HTML sectionsCustom HTML is removed for editors with the same filter. Every section the site uses has a component.
  • Change a section's side margins or widthSet once by contentSize 720px, wideSize 1,248px and a 96px gutter. Every template uses the same layout.
  • Reorder the fixed parts of a templateThe case study banner, stats, testimonial and related links stay in place: templateLock: "all" on the frame.

This already works on stamats.com

Pages a template builds come out the same every time. All 4 archive pages, all 11 team bios and all 7 webinar pages we measured line up to the pixel on a phone.

Pages people assemble by hand don't. The 27 one-off pages use 7 different phone margins. Case studies share a frame, but the middle is free, and their margins scatter too.

07Cause

Why the margins drift

Three things stack up. Any one of them would make pages inconsistent. Together they make it hard to build a page that matches the last one.

The template sets the width

The default template holds page content to a set width with side padding. Hero Cyan, a template made in the Site Editor and used on 7 pages, does not. A section placed on it only gets margins if someone wraps it first.

191spacer blocks used as gaps between sections, on 58 of 80 pages measured
388hand-set spacing values on 34 pages, 75 of them in the partner logo grid
13hand-set values every time the red CTA band is used

Spacing is typed in by hand

The child theme defines no spacing scale. Every gap is whatever the person building that page set on that block, so no two pages come out the same.

Raw HTML sections6 types
Core blocks with a class name9 types
Custom blocks with locked spacing0 found

Few sections are real components

Sections like the banner, stats row and FAQ are pasted HTML. Others are standard blocks with a class name added. Neither stops an editor from changing the spacing, so a body copy fix breaks the features built on top of it.
